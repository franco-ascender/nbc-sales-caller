# Caller context and approved answers

Scope: expand existing scenario briefs in Conversation Lab, preserving English UI and navy styling. No GHL/workflow/booking integration or paid calls are authorized by this change. Existing saved briefs remain compatible.

Acceptance: administrators can add business background, lead origin, qualification criteria, commercial boundaries, approved proof, next-step instructions and question/objection answers; save an immutable scenario version; select it from Make a Call without a reload; and use the same context for a browser test. Unsaved changes do not silently alter an active call. Empty business facts remain unknown rather than generated. The compiled prompt answers the question first, limits turn length, handles interruptions and opt-outs, and never claims an external action without a real tool receipt. Reference material from a different business cannot override this scenario.

Implementation: optional bounded context object in scenario JSONB; no schema migration. Pure browser-safe context schema/renderer shared by the server prompt compiler and editor preview; aggregate context budget enforced server-side. Only relevant caller routes receive a larger bounded JSON body, preserving ownership and admin checks. User scenarios are stored per owner and telephone slot creation snapshots the complete brief. Saving/selecting is not authorization to call.

Validation: parser/compilation tests for old/new briefs, oversize/invalid FAQ and guardrail precedence; fixture dispatch asserting complete context in phone/browser payloads; browser save/reload/select tests on desktop/mobile; read-only production verification. No paid provider jobs or voice sessions for these checks.

Delivered editor: six optional business-context fields, up to twelve question/objection answers, a 12,000-character additional-context budget and a readable preview. Partial answer rows block saving or selection. The starter uses the already configured Nalify brief; no new commercial claims were added. Saving creates a version; selecting a saved version opens its draft, and a separate action chooses it for the next browser test. The phone selector refreshes after saving and shows timestamps to distinguish versions.

Validation completed locally: 490 automated tests passing; production build passing; real save/session routes exercised against isolated HTTP fixtures with a payload above the former 8 KB boundary, owner checks, idempotency conflicts, malformed context and role restrictions. The telephone adapter receives the identical compiled context, including its final answer. Browser checks at 1440 and 390 pixels cover editing, incomplete-answer validation, add/remove, preview, save/reload, draft isolation and phone selection without refreshing the page or initiating calls. Read-only Retell configuration confirms its pinned LLM template consumes the per-call `nbc_scenario` variable. These checks verify plumbing and UI; actual conversational quality and latency still require user-run calls.
