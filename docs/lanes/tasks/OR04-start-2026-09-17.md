## Dinámica común

1. Franco selecciona el modelo inicial y pega el mensaje de arranque correspondiente. El lane lee su prompt completo en docs/lanes/prompts y esta asignación, reutilizando contexto existente.
2. El lane confirma alcance, modelo y primera entrega; empieza el trabajo autorizado e independiente. Si requiere subir o bajar modelo, pide explícitamente el cambio y espera antes de esa fase. No suponer que un prompt cambió el selector.
3. Cada entrega termina con un reporte corto en archivo: resultado, evidencia, límites y próxima tarea; modelo/costo conocido o desconocido. No copiar el informe entero entre chats. El lane dice a Franco qué ID terminó y ruta del reporte.
4. Franco trae al orquestador el ID/ruta. Root lee la entrega, revisa integración y devuelve correcciones o próximo encargo. Root no sustituye al implementador.
5. Franco revisa antes de push. Tests con gasto, cambios compartidos y publicación se concretan y coordinan según autorizaciones vigentes; falta de una credencial no paraliza el resto de trabajo. No llamadas a clientes ni campañas masivas en estos pilotos.
