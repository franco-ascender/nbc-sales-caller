## Resultado

Analytics Caller ahora tiene fondo azul noche NBC, trazos cian luminosos, curvas suaves, entrada animada, conteos animados, anillos y barras. Respeta reduced-motion. Las curvas atraviesan los valores observados sin sobrepasar sus extremos; no se agrega ruido para simular actividad.

**Customize** abre una galería de12 widgets: Pipeline leads, Conversations, Completed, Talk time, Pending results, Average duration, Conversation activity, Result mix, Pipeline distribution, Conversation channels, Daily talk time y Activity by hour. Hay10 por defecto. Se pueden agregar/quitar, arrastrar para ordenar y redimensionar con el tirador de esquina. Teclado: flechas en handle Move cambian orden; flechas en Resize ajustan ancho/alto. Save layout guarda por operador y modo Live/Demo; Cancel descarta borrador y Reset prepara defaults sin guardar automáticamente. Los previews de galería están identificados como ilustraciones.

CRM incorpora columnas teñidas por etapa, tarjetas redondeadas, identidad/contacto/última actividad y tarjeta flotante durante arrastre. Handles permiten mover tarjetas entre etapas, ordenar dentro del tablero y ordenar columnas. Las flechas izquierda/derecha de un lead cambian etapa; arriba/abajo cambian orden. Ficha lateral C04 y notas permanecen. Mover etapa conserva Do not call, usa CAS/idempotencia y registra autor/hora en actividad. El orden visual es preferencia, no altera estadísticas.

Persistencia **real**: configuración y orden en Supabase; cambios de etapa y actividad mediante contratos C04. Demo: datos ilustrativos C03 y fixtures de pruebas. No nueva telefonía, voz, ingresos ni campaña. El CRM sigue limitado a1.000 leads cargados y selección500; Analytics trabaja sobre sesiones cargadas, fechas locales y filtro7/14/30d/canal. Pipeline no sigue filtros de sesiones. Duraciones desconocidas se excluyen; promedio sin duraciones conocidas muestra «—». El gráfico horario representa hora de inicio, no tasa de respuesta. Orden/configuración Demo permanecen como preferencias al borrar mockdata, sin conservar actividad demo.

## Cómo lo revisa Franco

1. Abrir la URL inmutable con el login habitual de NBC. Como admin, Add mock data/Show demo data para ver información ilustrativa sin llamadas.
2. Caller → Analytics: observar entrada de curvas y números. Cambiar Period/Source para explorar; widgets de pipeline conservan su alcance de CRM.
3. **Customize** → Add Average duration o Pending results. Arrastrar el handle de un widget sobre otro; arrastrar la esquina para ancho/alto. Save layout, salir del tab y volver: conserva la configuración. En móvil se adapta a una columna y conserva tamaños desktop.
4. Volver a Customize, quitar un widget y Cancel: reaparece. Reset to default prepara la selección original; sólo Save layout la guarda. Si dos pestañas guardan la misma revisión, la segunda recibe conflicto con Reload saved layout.
5. CRM: arrastrar un lead por su handle hacia otra etapa; esperar Board saved. Abrir su ficha: mismo contexto y notas, nueva actividad del movimiento con autor/fecha. Un Do not call sigue bloqueado. Mover columnas por sus handles y ordenar tarjetas dentro de una columna; recargar para verificar persistencia.
6. Alternativa teclado: enfocar handle, flechas para mover; Resize permite flechas para ancho/alto. Escape cancela un arrastre. Revisar ficha lateral y edición de pipeline C04.
7. Revisar estética en desktop/móvil. Capturas locales `browser/{desktop,mobile}-{analytics,gallery,crm}.png`, todas DEMO. Nueva tabla `public.caller_views`:

| Campo | Tipo/constraint |
|---|---|
| operator_id | UUID FK auth.users ON DELETE CASCADE; parte de PK |
| is_demo | boolean not null default false; parte de PK |
| scope | text analytics/crm; parte de PK |
| config | JSONB objeto, tamaño SQL≤65536 bytes |
| version | UUID not null default gen_random_uuid() |
| last_request | UUID not null |
| last_payload | JSONB not null, privado para idempotencia |
| updated_at | timestamptz default clock_timestamp() |

PK(owner,modo,scope) sirve como índice de lectura. RLS habilitado; `revoke all ... from public,anon,authenticated`; service_role exclusivamente. RPC `caller_save_view(p_owner uuid,p_demo boolean,p_scope text,p_version uuid,p_request uuid,p_config jsonb)` SECURITY INVOKER, search_path public: advisory lock específico, comparación de versión, rechazo409 y reconocimiento de la última petición exacta. Tabla/RPC revocadas a clientes; permisos service_role. El backend obtiene owner del guard, nunca payload. El último request es idempotente; una petición de revisión anterior tras una nueva edición debe recargar.

| Método/ruta | Contrato |
|---|---|
| GET `/api/caller/views/analytics` o `/crm` | Bearer, miembro activo; query demo=true/false opcional. Demo sólo admin. Devuelve `{version:UUID|null,config}`. Si no existe, defaults privados en respuesta sin escritura. Analytics `{widgets:[{id,cols,rows}]}`; CRM `{order:UUID[]}`. |
| PUT mismas rutas | JSON≤64KiB `{requestId:UUID,version:UUID|null,demo:boolean,config}`. Catálogo cerrado12, sin duplicados, cols enteras3–12, rows2–6; máximo12 widgets. Orden CRM hasta1.000 UUIDs únicos; referencias no habilitan acceso a leads ajenos. Campos desconocidos de config se descartan. Devuelve versión/config guardadas. |

Errores400 scope/modo/shape/límites,401 sin sesión válida,403 membresía/Demo,409 revisión/request incompatible,413 tamaño,415 content type,503 lectura/escritura recuperable. JSON de errores saneado, no datos SQL/proveedor; no-store. No endpoint de borrar datos desde la galería: quitar widget modifica preferencias. Demo removal conserva esas preferencias.

CRM reutiliza PATCH `/api/caller/leads/[id]/details` y PUT `/api/caller/pipeline` C04 sin cambio de contrato. Mover etapa y guardar orden son dos escrituras, no una transacción conjunta: si etapa queda guardada y orden falla, la UI lo dice y reintenta orden, sin duplicar evento. Edición de buckets sigue transaccional C04. Orden guardado contiene como máximo leads cargados; nuevos leads se agregan tras los que ya tienen orden.

No variables nuevas: runtime `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`; administración local `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`, `VERCEL_TOKEN`, `VERCEL_TEAM_ID`, `VERCEL_PROJECT_ID`.
