Fecha: 2026-09-15, macOS/Chrome y build aislado Next16.3.5. Autor: Codex, un escritor, sin subagentes. Request directo de Franco: no pedir login al abrir nuevas pestañas durante12h. ## Resultado

Login explícito abre ventana fija de12h, compartida entre pestañas del mismo navegador/perfil/origen. Supabase persiste sesión/refresh token con adapter localStorage específico NBC; contraseña nunca se persiste. Refresh/reload/nueva pestaña no prolongan expiresAt; un refresh tardío no resucita una sesión eliminada/expirada. Nueva pestaña muestra Checking your session mientras restaura y valida identidad/membresía en el servidor. Rechazo401/403 elimina persistencia, fallo503 permite reintentar sin mostrar datos. Logout limpia y se propaga entre pestañas; vencimiento se comprueba cada segundo y al recuperar foco/visibilidad.

La duración controla la restauración del portal; no cambia la expiración JWT ni configura una revocación global de Supabase a12h. APIs conservan verificación independiente de token/membresía, no confían en localStorage como autorización. Otro navegador/dispositivo o incógnito requiere login propio. Tras actualizar, una sesión antigua en memoria necesita iniciar sesión una vez para crear persistencia nueva.
