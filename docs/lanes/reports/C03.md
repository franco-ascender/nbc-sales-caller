## Cómo lo revisa Franco

1. Abrir URL de Caller y entrar con el mismo login del dashboard, rol admin. Pulsar **Add mock data**. Aparece banda DEMO,32 leads y24 resultados ilustrativos. **Show live data** permite volver; no mezcla datasets.
2. CRM → seleccionar casillas o **Select all filtered leads** → **Save as list**, nombrarla → **Create list**. Usar **Send to AI Caller**. Alternativamente, AI Caller → **Load from CRM** o **Saved CRM list**. DNC/Won/Lost se excluyen de la cola.
3. **Turn on AI Caller · Demo** → una fila Calling y luego Completed; **Stop demo** detiene. **View call & transcript** abre resultado. Es simulación; no llama ni cobra. En Live, la acción real informa conexión telefónica pendiente. **Upload leads** abre importador del CRM; CSV real solo en Live.
4. Analytics → cambiar período/fuente y seleccionar días. Gráficos muestran el dataset cargado. En AI Caller → **Conversation history**, Load more amplía historial; mantiene filtros y export final solo para resultados reales verificados.
5. Dialer → **Record call** → leer límite de llamada externa → **Record audio**, permitir micrófono, hablar, Stop, escuchar/descargar. Es nota local. Cancel/Discard o salir cancela/cierra micrófono.
6. Voices → **Clone my voice**, seguir guía, grabar/adjuntar muestra propia, escuchar y nombrarla. **Refresh voices** reconsulta plan. Si el proveedor habilita clonación, consentimiento + **Create my voice copy** envía la muestra y puede consumir el plan; esa acción no fue ejecutada por el lane. Si exige verificación, la voz no puede activarse todavía.
7. **Remove mock data** elimina únicamente fixtures propios, incluso listas demo; no borra leads reales ni datos de otro admin. Repetir agrega/quita para revisar estados vacío/con datos.

## Datos, APIs y configuración

Migración `202609140050_caller_operations.sql`: **PROBADA AISLADA / APLICADA**, SHA256 `7e426a2960703ae02195462050f12ac2cc94766a545871d9e122069bcaf72fec`.

- `caller_leads.is_demo`, `call_sessions.is_demo`: bool NOT NULL DEFAULT false. `call_sessions.lead_id` FK nullable a lead, DELETE SET NULL.
- `caller_lead_lists`: UUID, owner FK auth, nombre1..100, modo, fechas; UNIQUE(id,operator_id).
- `caller_lead_list_items`: PK(list_id,lead_id), owner; FK compuestas a listas/leads por UUID+owner, DELETE CASCADE. Leads reciben índice UNIQUE(id,operator_id).
- RLS activo en ambas tablas nuevas; sin grants a public/anon/authenticated. SELECT/INSERT/UPDATE/DELETE y funciones solo service_role. Tablas leads/sessions reciben DELETE para RPC admin; endpoint siempre usa owner verificado.
- RPC `caller_save_list(uuid,uuid,text,uuid[],boolean)`: lock por owner, valida1..500 IDs únicos/propios/mismo modo; upsert y reemplazo de integrantes transaccional. Un UUID ajeno no se reutiliza.
- RPC `caller_demo_set(uuid,boolean)`: lock por owner, alta idempotente, conflicto teléfono conserva original, baja solo owner+is_demo. No contacto externo.
- Voice jobs: `kind` design/clone, `sample_hash`, `needs_verification`, `failure_code`; status agrega failed. No audio binario ni transcripción de muestra.
